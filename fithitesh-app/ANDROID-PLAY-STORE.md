# FitHitesh — Android app & Google Play launch

FitHitesh is now a **native Android app** (built with Capacitor). The whole web app in `www/` is packed *inside* the app, so:

- no website or hosting is needed, no `assetlinks.json`, no address bar;
- it works fully offline from the first launch (fonts are bundled too);
- barcode scanning uses Google's built-in code scanner (no camera permission needed);
- **Export backup / CSV** opens Android's share sheet (save to Drive, Files, Gmail…);
- the phone's **back button** closes open sheets.

GitHub builds the app for you. Nothing needs to be installed on your computer.

```
fithitesh-app/
├── www/                     ← the app (index.html, privacy.html, icons, fonts)
├── android/                 ← Android project (generated by Capacitor)
├── assets/                  ← source images for launcher icon + splash
├── play-store/              ← icon, feature graphic, 5 phone screenshots
├── capacitor.config.json    ← app ID com.hitesh.fithitesh, name
└── package.json
.github/workflows/fithitesh-android.yml   ← cloud build (APK + AAB)
```

---

## Step 1 — Turn on signed builds (one time, 5 min)

You received **fithitesh-upload-key.zip** in the chat. It holds your *upload key* and its passwords.

1. Save the zip in **two** safe places (Google Drive + USB). Do not put it in GitHub.
2. Open `UPLOAD-KEY-SECRETS.txt` inside it.
3. On GitHub open this repository → **Settings → Secrets and variables → Actions → New repository secret** and add the 4 secrets listed there (`FITHITESH_KEYSTORE_BASE64`, `FITHITESH_KEYSTORE_PASSWORD`, `FITHITESH_KEY_ALIAS`, `FITHITESH_KEY_PASSWORD`).

## Step 2 — Build

Every push that changes `fithitesh-app/` builds automatically. To build by hand: **Actions → FitHitesh Android build → Run workflow** (shows once the workflow is on the default branch) — or just re-run the latest run.

When the run is green, scroll to **Artifacts** at the bottom of the run page:

| Artifact | Use |
|---|---|
| `fithitesh-apk` → `app-debug.apk` | Copy to your Android phone and install (allow "install unknown apps") to try it |
| `fithitesh-aab` → `app-release.aab` | Upload to Google Play |

The version code goes up automatically with each run, so every new `.aab` can be uploaded.

## Step 3 — Test on your phone

Install `app-debug.apk` and check:

- [ ] First-run screen, then log food, water, a workout, a sport session and a weigh-in
- [ ] Barcode: Food → Scan → *Open camera scanner* (first time Google may download the scanner module — wait a minute)
- [ ] Settings → Export backup opens the share sheet → save to Drive
- [ ] Settings → Import backup restores it
- [ ] Airplane mode: the app still opens and works
- [ ] Back button closes a sheet; on the main screen it leaves the app

## Step 4 — Google Play Console

1. **Developer account** at play.google.com/console — one-time US$25, ID verification.
   - A new **personal** account must run a **closed test with at least 12 testers for 14 days in a row** before it can publish to everyone. Line up 12 friends / JDS classmates with Android phones now.
   - An **organisation** account (needs a D-U-N-S number) skips that rule.
2. **Create app** → name *FitHitesh*, App, Free.
3. **Test and release → Closed testing → Create release** → upload `app-release.aab`. Accept **Play App Signing** (Google keeps the final signing key; yours is only the upload key, and Google can reset it if you ever lose it).
4. Add your 12+ testers (a Google Group or email list), roll out, send them the opt-in link. Keep it running 14 days.
5. Then **Production → Apply for production access**, answer the questions, and roll out.

### Privacy policy URL

Google needs a public web link. Easiest options:

- **Netlify Drop** (free): app.netlify.com/drop → drag the `www` folder → use `https://<name>.netlify.app/privacy.html`; or
- **GitHub Pages**: needs a public repository (this research repo holds other files, so better to make a small public repo with just `privacy.html`).

**Before publishing, replace `YOUR-EMAIL@example.com` in `www/privacy.html` with your contact email.**

## Updating the app later

1. Edit files in `www/` (food list, routines, colours — see `WEB-README.md`).
2. Commit and push → GitHub builds a new `.aab` automatically.
3. Play Console → your track → *Create new release* → upload it.

For the web (browser/PWA) version, `WEB-README.md` still applies; remember to bump `VERSION` in `www/sw.js` there.

## Developer notes

- After changing `www/` locally: `npm ci && npx cap sync android` (CI does this).
- Icons/splash are generated from `assets/` with `npm run icons`.
- `android/app/build.gradle` signs the release only when the `FITHITESH_*` env vars are set, and takes `-PversionCode` from CI.
- Steps / Health Connect: add a Capacitor Health Connect plugin later if you want automatic step counts.
